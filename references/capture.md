# Сценарий и съёмка интерфейса

Скрипт снимает области реального интерфейса в локальном стенде. Он не подключается
к порталу, не читает токены и блокирует сеть. Подготовка стенда зависит от приложения:
её выполняет агент средствами сборки целевого проекта.

1. Скопируйте `templates/storyboard.md` и `templates/capture.example.json` в
   `out/<статья>/` целевого проекта. Для каждого снимка определите действие,
   состояние, область и подпись. Число снимков выбирайте по задаче.
2. Соберите локальный стенд из настоящих компонентов приложения. Подставьте
   демонстрационные документы и результаты через поддерживаемые props, workflow
   или mock API. Не меняйте защиту и маршруты рабочего приложения ради снимков.
3. Получите один браузерный JS-бандл (IIFE, без внешних импортов) и локальные CSS.
   Пути укажите в `fixture.script` и `fixture.styles`. Скрипт создаёт `#app`,
   подключает стили и JS без сервера. Шрифты и изображения также должны быть
   встроены в бандл/CSS через data URL; внешние ресурсы будут заблокированы.
4. В стенде реализуйте `window.renderFixture(scene)`: она размонтирует предыдущий
   экземпляр, монтирует настоящий компонент с данными выбранной сцены и ждёт
   готовности состояния. Это тестовый hook только локального стенда, не рабочего сайта.
5. Запустите `scripts/capture.mjs <capture.json>` из установленного умения.
   Проверьте PNG при масштабе, который будет в статье, и `capture-evidence.json`.
   Большую карточку лучше снять отдельно, чем уменьшать целый экран до нечитаемости.

## Поля capture.json

Все пути разрешаются относительно файла конфигурации.

| Поле | Назначение |
|---|---|
| `fixture.script` | Локальный IIFE-бандл настоящего интерфейса |
| `fixture.styles` | Массив локальных CSS-файлов |
| `fixture.sceneHook` | Имя функции сцены, по умолчанию `renderFixture` |
| `source` | Какой компонент или экран снимаем |
| `data` | Описание данных, например `synthetic` |
| `viewport` | `width`, `height`, `deviceScaleFactor`; по умолчанию 1180×1040, 2× |
| `output`, `evidence` | Каталог PNG и путь отчёта; по умолчанию `images/` и `capture-evidence.json` |
| `adapter` | Необязательный локальный модуль с `prepareShot({ page, shot })` |
| `shots` | Список кадров с уникальными `id`, `selector`, `caption`; необязательные `scene`, `viewport`, `actions`, `settleMs` |

`actions` выполняются после подготовки сцены и адаптера. Есть два вида действий:
`{ "click": ".selector" }` и `{ "clickText": "Точный текст кнопки" }`.
Отсутствующая кнопка вызывает ошибку. Для ввода файла, выбора находки и других
действий экспортируйте `prepareShot` из проектного адаптера:

```js
// Адаптер живёт в материалах статьи, а не в рабочем приложении.
export async function prepareShot({ page, shot }) {
  if (shot.input) await page.locator(shot.input.selector).fill(shot.input.value);
  // Здесь можно вызвать тестовый workflow стенда или дождаться нужного состояния.
}
```

Адаптер — обычный исполняемый код: используйте свой или проверенный модуль.
Ожидание переходов настраивается `settleMs` (0–10000 мс, по умолчанию 450).
`viewport` кадра переопределяет общие настройки. Скрипт завершится с ошибкой, если
область не найдена, пуста или интерфейс сообщил JS-ошибку. Отчёт содержит размеры,
подписи, источник, тип данных и число заблокированных запросов. При неудаче могут
остаться частичные PNG; успешным результатом считайте только завершившуюся команду.

## Сборка Vue / B24 UI

Используйте Vite и плагины из целевого проекта, задав `build.lib.formats: ['iife']`
и отдельный каталог результата внутри материалов статьи. Компонент и его стили
импортируются из исходников проекта. Для применённой версии B24 UI в исходной
статье потребовалось `experimental: { componentDetection: false }` в Vite-плагине;
это настройка отдельной сборки стенда, не требование менять сборку приложения.

Полный видеопроцесс, layout.json, Remotion, таймлайн и звук здесь не используются.
